# Interaction Flow

> Auto-generated by tracing gameplay loops in the Unity project. Regenerate with "init context".

## 1) Startup And State Restore

1. `LoadingScene.Start()` loads target scene (default: `DevScene_QuestMachine`).
2. `SaveManager.Awake()` loads JSON save data or creates default.
3. `GameManager.Start()` starts `CoInitialize()` coroutine.
4. `CoInitialize()` finds `PlayerController` and `Restaurant` in scene.
5. `Restaurant.SetInfo(RestaurantData)` restores:
   - Unlockable states (Hidden/ProcessingConstruction/Unlocked)
   - Tutorial state
   - Quest progress binding
   - Worker count (spawns workers)
6. `GameManager` starts periodic autosave loop (every 10 seconds).

## 2) Core Service Loop (Order -> Produce -> Serve -> Reward -> Maintain)

### Order

1. `Counter.CoSpawnGuest()` spawns guests into queue positions every ~1 second.
2. `Counter.UpdateGuestOrderAI()` checks front guest:
   - If no clean plate available -> guest shows "No Plate", blocks.
   - If clean plate available -> consumes one plate, generates `CustomerOrderState`.
3. Order is composed of recipe categories (`Main`, `Side`, `Drink`), at most one recipe per category, at least one total.
4. Recipes selected from `Counter.recipeDatabase` (DatabaseRecipeData).
5. Front guest shows remaining recipe names in order bubble (`OrderText`), colored by category: Brown=Main, Orange=Side, Red=Drink.

### Produce

1. `IngredientStation` auto-spawns ingredient items to its pile (while count < maxSpawned), unless `nonAutomatic` is enabled.
2. Player/worker interacts with station -> `OnWorkerIngredientInteraction()` transfers pile item to tray.
3. For processing stations (e.g., Grill):
   - `IngredientAbsorber` consumes specific ingredient from tray (e.g., raw patty).
   - `OnIngredientAbsorbed` triggers `TimedObjectBehavior.StartTime()`.
   - On timer completion (`onTimeEnd`): processing resets, output station spawns result (e.g., cooked patty).
4. Grill-specific: Empty -> Cooking (10s) -> Cooked (pickup available) -> Burned (30s, becomes trash).
5. SinkStation: IngredientAbsorber takes dirty dish -> timed wash -> outputs clean plate.

### Serve

1. Worker/player interacts with counter cashier trigger (`OnGuestInteraction`).
2. `Counter.TryDeliverIngredientsFromTray()` validates:
   - Active order exists for current front guest.
   - Tray contains ingredients matching remaining recipe requirements.
3. Ingredients consumed only when a **full recipe** can be completed from current tray counts.
4. Completed recipe removed from remaining order display.
5. When all recipes completed and an eligible clean table exists:
   - Guest served and routed to table via `FindTableToServeGuests()`.
   - Money spawning scheduled: `_spawnMoneyRemaining = Max(1, TotalRecipeCount) * 10`.
6. Burger visual still spawned for compatibility regardless of recipe type.

### Reward

1. `Counter.CoSpawnMoney()` spawns money objects to MoneyPile over time.
2. Player/worker picks up money via pile interaction (`PileToTray`).
3. Money delivered to deposit point -> `GameManager.Money` increases.
4. `GameManager.BroadcastEvent(MoneyChanged)` triggers.
5. `UI_GameScene.RefreshUI()` updates money display.

### Maintain

1. After eating finishes (5-11s), `Table` spawns trash and dirty dishes, becomes `Dirty`.
2. Player/worker collects trash via table interaction (`PileToTray`).
3. Trash dropped in `TrashCan` (despawned with jump animation).
4. Dirty dishes taken to `SinkStation` for washing (if present).
5. When all trash cleared, table returns to `None` (available for new guests).
6. Clean plates returned to `CleanPlatePile` to enable future orders.

## 3) Worker Automation Loop

1. Worker hired via `HireWorker` event -> `Restaurant.OnHireWorker()` spawns worker.
2. `Restaurant.CoDistributeWorkerAI()` runs every 1 second:
   - Scans `RestaurantSystems` for systems with pending jobs (`HasJob`).
   - Assigns idle workers to systems.
3. `MainCounterSystem.DoMainCounterWorkerJob()` assigns worker to highest-priority job:
   - **MoveBurger**: Navigate to Grill -> pick up cooked patty -> bring to Counter.
   - **CounterCashier**: Navigate to Counter -> serve guests / collect payment.
   - **CleanTable**: Navigate to dirty Table -> pick up trash -> bring to TrashCan.
4. Worker executes coroutine job: navigate -> wait at interaction point -> complete action.
5. When no jobs remain, worker becomes idle and is removed from system assignment.

## 4) Construction/Unlock Flow

1. Locked station starts in `Hidden` or `ProcessingConstruction` state.
2. Player/worker enters `UI_ConstructionArea` trigger zone.
3. At each interaction interval, cost chunk deducted from player money.
4. `UI_ConstructionArea` updates slider and remaining cost text.
5. On completion (spentMoney >= totalCost):
   - `UnlockableBase.SetUnlockedState(Unlocked)` activates the prop.
   - Construction UI hides.
   - `UnlockProp` event broadcasts.
   - Quest Machine message sent: `unlockableStation / unlocked / <questDataID>`.
   - Quest progress hooks fire.

## 5) Ingredient Station Flow

1. `IngredientStation` in auto mode: spawns ingredient items at `spawnInterval` while pile count < maxSpawned.
2. `IngredientStation` in manual mode (`nonAutomatic = true`): only spawns via explicit `SpawnIngredientToPile()` calls (e.g., from cooking timer completion).
3. Worker/player interaction transfers from pile to tray.
4. `IngredientAbsorber` on processing stations:
   - Checks tray for matching ingredient by ID.
   - Consumes one item, despawns it, increments currentItemCount.
   - Fires `OnIngredientAbsorbed` callback (typically starts timed process).
5. `IngredientPileAbsorber` variant: takes items from source pile instead of tray.

## 6) Quest Progress Hooks

- **Old quest hooks** (still present in code):
  - `PileBase.UpdateQuestProgress()` on pickup/drop.
  - `UI_ConstructionArea.UpdateQuestProgress()` on construction complete.
  - `QuestUpdaterComponent` calls in various components.
- **Quest Machine hooks** (active in dev scene):
  - `UnlockableBase` sends message on unlock: `unlockableStation / unlocked / questDataID`.
  - `IngredientStation` sends quest gameplay messages on ingredient pickup.
  - `TutorialMoneyPile` sends picked-up-money gameplay message.
  - Custom quest actions can unlock stations (`QuestActionSetUnlockableState`) or grant rewards (`QuestActionGiveReward`).

## 7) Common Debug Entry Points

- **Money issues**: `GameManager.Money` setter -> `UI_GameScene.RefreshUI()`
- **Worker not doing anything**: `Restaurant.CoDistributeWorkerAI()` -> `MainCounterSystem.HasJob` / `DoMainCounterWorkerJob()`
- **Guests not being served**: `Counter.FindTableToServeGuests()` -> `_currentOrder` completion state -> `Counter.TryDeliverIngredientsFromTray()` ingredient-match logic
- **No orders starting**: `Counter.UpdateGuestOrderAI()` -> `CleanPlatePile` availability check
- **Unlock stuck**: `UI_ConstructionArea.OnWorkerInteraction()` -> `UnlockableBase.SetUnlockedState()`
- **Save/load mismatch**: `SaveManager.LoadGame()/SaveGame()` -> `Restaurant.SetInfo()`
- **Cooking not working**: `Grill.Update()` state transitions -> `IngredientAbsorber.Absorb()` -> `TimedObjectBehavior`
- **Quest not progressing**: `QuestMachineManager` -> message sender/parameter match -> `QuestActionSetUnlockableState`
