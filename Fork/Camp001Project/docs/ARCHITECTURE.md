# Architecture

> Auto-generated by reading key scripts in the Unity project. Regenerate with "init context".

## Runtime Entry And Scene Flow

- Editor play mode starts from `Assets/@Scenes/LoadingScene.unity` (forced by `PlayFromLoadingScene`).
- `LoadingScene` loads target scene via serialized `_targetSceneName` (default: `DevScene_QuestMachine`).
- `SaveManager.Awake()` loads save data or creates default save.
- `GameManager.Start()` runs `CoInitialize()`: finds PlayerController and Restaurant, calls `Restaurant.SetInfo()`, starts autosave loop.

## Layered Architecture

### 1) Global Managers

- **SaveManager** (Singleton):
  - Owns serialized save model: `GameSaveData` -> `RestaurantData` -> `UnlockableStateData`.
  - JSON save/load in `Application.persistentDataPath/SaveData.json`.
  - Fixed capacities: MAX_STAGE = 10, MAX_PROPS = 20.
  - DontDestroyOnLoad.

- **GameManager** (Singleton):
  - Runtime coordinator and event hub (`EEventType`: MoneyChanged, HireWorker, UnlockProp).
  - Holds references to Player, Restaurant, key prefabs, main UI.
  - Resolves scene objects, applies save state into Restaurant.
  - Routes spawn/despawn to PoolManager.
  - Auto-saves every 10 seconds.
  - Money property broadcasts MoneyChanged on change.

- **PoolManager** (Singleton):
  - Object pooling for workers/guests/money/trash/burgers/ingredients.
  - Addressables-backed prefab loading with async cache/release.

### 2) World/System Layer

- **Restaurant**:
  - Aggregates child `SystemBase` modules and `UnlockableBase` props.
  - `SetInfo(RestaurantData)`: restores unlockable states, tutorial state, quest progress, worker count.
  - `CoDistributeWorkerAI()`: every 1 second, scans systems for pending jobs and assigns idle workers.
  - `OnHireWorker()`: spawns new worker, updates save data.

- **MainCounterSystem** (SystemBase):
  - Core kitchen/front-desk automation. References: Grill, Counter, Tables, TrashCan, Office, IngredientStationsHolder.
  - Three job types: `MoveBurger` (grill -> counter), `CounterCashier` (serve guests), `CleanTable` (pickup trash).
  - `DoMainCounterWorkerJob()`: main coroutine assigning workers to highest-priority available job.

- **TimedObjectBehavior**:
  - Generic timed process. Duration, worker-presence gating, start/end/progress callbacks.
  - Used by Grill (cooking timer) and SinkStation (washing timer).

### 3) Actor Layer

- **StickmanController**: Base actor. NavMeshAgent movement, animation state (Idle/Move/Eating), tray reference, order bubble.
- **WorkerController** (extends StickmanController): Adds coroutine job execution (`DoJob()`), system ownership (`CurrentSystem`).
- **PlayerController** (extends WorkerController): Disables NavMeshAgent, uses CharacterController + joystick input. WASD in editor. 45-degree input rotation.
- **GuestController** (extends StickmanController): States: None -> Queuing -> Serving -> Eating -> Leaving.

### 4) Interaction/Object Layer

- **WorkerInteraction**: Trigger enter/exit detection. Repeated `OnInteraction` callback at configurable interval. Core interaction primitive for all stations/piles.

- **UnlockableBase**: State machine: Hidden -> ProcessingConstruction -> Unlocked. Integrates with construction UI, Quest Machine messages, and save state.

- Main props:
  - **Counter**: Guest queue, recipe-based order generation (CustomerOrderState), ingredient delivery validation, table routing, money spawning. Clean plate gating via CleanPlatePile.
  - **Grill**: Cooking states: Empty -> Cooking (10s) -> Cooked -> Burned (30s). Worker interaction for raw/cooked patty.
  - **Table**: Guest seating/eating (5-11s), trash/money generation, dirty state management.
  - **IngredientStation**: Auto-spawn or manual mode. Worker pickup with quest messaging.
  - **SinkStation**: Dish cleaning via IngredientAbsorber + TimedObjectBehavior.
  - **Office**: Opens employee upgrade popup.

### 5) Item Transport Layer

- **TrayController**: Carried stack with DOJump animations. Type constraints (one EObjectType at a time). `GetIngredientCounts()` for recipe matching.
- **PileBase** (+ BurgerPile, MoneyPile, TrashPile, IngredientPile, CleanPlatePile): World stack container. Configurable grid layout. SpawnObject, TrayToPile, PileToTray, DespawnObject.
- **TrayItemBehavior**: Per-item metadata (canBeTrash, IngredientData reference).

### 6) UI Layer

- **UI_GameScene**: Main HUD — money display, toast messages, Quest Machine journal binding.
- **UI_Joystick**: Mobile virtual joystick, writes to GameManager.JoystickDir.
- **UI_ConstructionArea**: Construction spending/progress. Deducts money per worker interaction tick.
- **UI_OrderBubble**: World-space order text above guests.
- **UI_TimerProgress**: Circular fill for timed processes.
- **UI_FaceCameraRotate**: Billboard rotation for world-space UI.
- **UI_UpgradeEmployeePopup**: Employee upgrade screen.

## Quest Architecture

Two quest implementations coexist:

- **Legacy custom quest system** (`OldQuestSystem/`): QuestJournal, QuestData, QuestUpdaterComponent. Still referenced in gameplay components (PileBase.UpdateQuestProgress, UI_ConstructionArea.UpdateQuestProgress).
- **Active: Pixel Crushers Quest Machine** (`Quest Machine System/`):
  - `QuestMachineManager` (Singleton): Initializes journal from level quest database.
  - Custom quest actions:
    - `QuestActionSetUnlockableState`: Changes prop state (uses UniTask to wait for GameManager init).
    - `QuestActionGiveReward`: Grants rewards via QuestMachineManager.
  - Message pattern for station unlock: sender `unlockableStation`, message `unlocked`, parameter = `QuestMachineQuestData` asset name.

## Data Model And Persistence

- **Save structure** (GameSaveData):
  - Global: money, currentRestaurantIndex, playerPosition
  - Per-restaurant (RestaurantData): workerCount, tutorialState, unlockableStates list, questProgress list
  - Per-unlockable (UnlockableStateData): state enum, spentMoney
  - Per-quest (QuestProgress): questID, isCompleted
- **ScriptableObject config types**:
  - ConstructionCostData: building costs
  - IngredientData + DatabasePile: ingredient catalog
  - RecipeData + DatabaseRecipeData: recipe catalog
  - QuestMachineQuestData: quest definitions

## Eventing And Messaging

- **In-project event bus**: `GameManager.AddEventListener / BroadcastEvent(EEventType)`.
  - Event types: MoneyChanged, HireWorker, UnlockProp.
- **Quest Machine messaging**: `PixelCrushers.MessageSystem`.
  - `UnlockableBase` sends `unlockableStation / unlocked / <questDataID>` on unlock.
  - `IngredientStation` sends quest gameplay messages on ingredient pickup.

## Notable Constraints / Caveats

- `Singleton<T>` auto-creates objects if not present; most core singletons are scene-authored.
- Save initialization uses fixed capacities (MAX_STAGE = 10, MAX_PROPS = 20).
- `Define.WORKER_SPAWN_POS` and `Define.GUEST_LEAVE_POS` are static constants at `(0,0,0)`.
- Build settings include TitleScene and DevScene_QuestSystem but LoadingScene targets DevScene_QuestMachine by default.
- PlayerController applies 45-degree rotation to input direction.
- Grill burns after 30s if cooked patty is not picked up.
- Counter requires clean plate availability before generating a new order.
